# Security and privacy

Use an ordinary user account. No administrator privileges, security-policy changes, shell endpoint, remote control, microphone or transcript scanning are required. The monitor observes only an explicitly selected process and checks its creation identity. It does not launch models, kill inference processes or expose network listeners.

Keep `runs/` private. Before publishing modifications, run privacy/secret scans and inspect the staged file list. Report vulnerabilities privately to the repository owner when private reporting is available; never post tokens, machine paths, process dumps or raw private traces in Discussions.
